## Systems of record

- Account: identity, authentication context, roles, and permissions.
- My Assets: free balance, buying power, reservation/release, asset positions.
- Contracts: legal contracts and obligations.
- Services: transport, storage, inspection, insurance, installation, delivery.
- Settlement: authoritative financial settlement execution and result.
- Official institutions: authoritative legal registration or official records,
  where applicable.
- General Market: market workflow, offers, orders, matching, trades, references,
  execution policy, and coordination states.

## Mandatory design constraints

1. The client is not authoritative for permissions, buying power, matching,
   or state transitions.
2. Financial and asset balances must not be independently duplicated here.
3. External operations require explicit contracts, timeouts, error handling,
   correlation identifiers, and safe retry behavior.
4. Concurrent order and matching operations require transactional safeguards
   and idempotency.
5. Published configuration and execution policy versions must be traceable.
6. Important transitions must be auditable without copying complete external
   records unnecessarily.
7. Database migrations must be versioned, reviewable, and non-destructive by
   default. Never rebuild or erase an existing database automatically.
8. Redis and message brokers are optional; introduce them only after a
   measured technical requirement.
9. A directory or README is not a completed feature. Each module needs code,
   API contracts where applicable, automated tests, and acceptance checks.
10. Infrastructure adapters must have a single clear location. If an older
    implementation exists under internal/database, review imports and behavior
    before consolidating or moving it to infrastructure/postgres.

## Implementation order

1. Inspect current repository, Go packages, migrations, configuration, and API.
2. Stabilize application bootstrap, PostgreSQL access, errors, logging, health,
   and test harness.
3. Implement catalogue and market/offer configuration.
4. Implement offers and eligibility.
5. Implement supply requests, orders, reservations, and matching.
6. Implement trades, state machines, execution policies, and workflows.
7. Add integrations, commodity aggregation, real-asset workflows, and audit
   coverage as required by the detailed specification.
8. Verify concurrency, security, performance, migrations, and recovery.

This document defines logical responsibilities, not separate deployable
services. Go package boundaries must remain simple and avoid circular imports.
